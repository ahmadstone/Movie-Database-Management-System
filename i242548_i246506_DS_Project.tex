\begin{abstract}
This paper presents a comprehensive Movie Database Management System that efficiently handles large-scale movie metadata through proper CSV parsing, hash tables and AVL trees, and a similarity graph constructed using shared actors and genres. The system supports fast searches, personalized movie recommendations via BFS, and shortest path discovery between any two movies. Key contributions include properly cleaning the CSV file, O(n²) graph construction for semantic similarity, and O(1) lookups using hashing with chaining.
\end{abstract}

\section{Methodology}

This section describes the five fundamental algorithmic components of the system.

\subsection{CSV Parsing and Data Loading}

Robust parsing of \texttt{movie\_metadata.csv} containing quoted fields and escaped quotes.

\begin{itemize}
    \item \textbf{\texttt{getNextField()}} — Extracts fields handling escaped quotes:
\begin{lstlisting}[caption={getNextField() — Core CSV field extractor}]
static string getNextField(const string& line, size_t& pos) {
    if (pos >= line.size()) { ++pos; return string(); }
    string field = "";
    if (line[pos] == '"') {
        ++pos;
        while (pos < line.size()) {
            char c = line[pos];
            if (c == '"') {
                if (pos + 1 < line.size() && line[pos + 1] == '"') {
                    field.push_back('"'); pos += 2; continue;
                } else { ++pos; break; }
            } else { field.push_back(c); ++pos; }
        }
        while (pos < line.size() && line[pos] != ',') ++pos;
        if (pos < line.size() && line[pos] == ',') ++pos;
    } else {
        while (pos < line.size() && line[pos] != ',') {
            field.push_back(line[pos++]);
        }
        if (pos < line.size() && line[pos] == ',') ++pos;
    }
    return field;
}
\end{lstlisting}

    \item \textbf{\texttt{cleanField()}} — Removes surrounding quotes, replaces non-breaking spaces, and trims whitespace.
\end{itemize}

The \texttt{loadFromCSV()} function orchestrates parsing and populates all data structures.

\subsection{Hash Table with Chaining (DJB2)}

Multiple hash tables enable $O(1)$ average lookup by title, actor, director, genre, and year.

\begin{lstlisting}[caption={DJB2 Hash Function}]
int hashFunction(const string& key) const {
    unsigned long hash = 5381;
    int c;
    const char* str = key.c_str();
    while ((c = *str++))
        hash = ((hash << 5) + hash) + c;  // hash * 33 + c
    return hash % tableSize;
}
\end{lstlisting}

Search performs case-insensitive exact matching within collision chains.

\section{Results}
The system successfully loads ~5,000 movies, builds a dense similarity graph, and provides sub-second responses for all search and recommendation queries. BFS-based recommendations yield meaningfully similar movies, and shortest-path queries reveal interesting actor/genre connections (e.g., "six degrees of separation"-style chains).

\section{Discussion}
The resilient CSV processing along with different indexing methods and graph reasoning has combined together to create a wealth of functions but with still great performance. The O(n²) graph creation is tolerable for the dataset size that is set and may be further developed with sampling or approximate techniques for larger collections of texts.

\section{Conclusion}
A complete movie database system has been implemented which is advanced and demonstrates the practical use of the fundamental algorithms and data structures: robust parsing, efficient indexing, and graph traversal. The system is a good platform for the exploration of relationships in movie metadata.
